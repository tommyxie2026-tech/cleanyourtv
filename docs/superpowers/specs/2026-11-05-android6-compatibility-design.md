# CleanYourTV Android 6+ 兼容方案

日期：2026-11-05

## 目标与范围

基于 `tommyxie2026-tech/cleanyourtv` 的 `fc148d5a9707b30e8f49f489625947421740dc55`，适配仓库中的 `launcher/` 桌面应用，使安装及运行最低要求为 Android 6.0（API 23），并保留现有界面、遥控器导航和功能。Android 7 及更高版本共用同一代码库；系统不提供的能力明确降级，不伪装为可用。

本轮不将电脑端精简脚本改成手机管理应用，不移植全部独立附加应用，不刷机、不取得 root、不停用极米原桌面，也不改变冰箱已有冻结状态。

## 方案比较与选择

1. **兼容层方案（用户已选）**：延续原桌面，在运行库与系统调用边界增加兼容处理；保留后续合并上游的能力。代价是增加兼容代码，运行库回填可能增大安装包。
2. **精简重写方案**：仅保留应用网格、遥控器和设置入口，维护面较小，但丢失现有主题及其他功能，故不采用。

## 改动设计

- 将桌面应用的最低版本设为 API 23，保持现有 targetSdk；保留设备能力检查和原桌面保护逻辑。
- 回填 `java.time` 等旧 Android 缺失的 Java 标准库接口；文件读取按需采用传统流实现。使用 Android lint 检查整个桌面源码和资源，修复全部新增的高版本 API 兼容错误。
- Android 6 的网络状态监听使用该系统支持的回调方式；分别管理注册、注销，避免网络切换后状态失效。
- Android 6 不存在文件级加密的解锁阶段：用户解锁检查视为可用；Android 7+ 保持现有解锁检测。无障碍服务退出、通知监听与重绑定等按系统能力降级。
- 检查应用发现、设置和 HDMI 入口在 H2 上的适用性；厂商专属入口通过现有配置表达，不在通用代码中硬编码。增加普通应用入口，使缺少标准 Android TV 应用列表支持的设备也可手动打开。
- 在本地分支维护这次兼容改造，记录与上游 API 26 限制的区别。运行库兼容依赖作为此分支的明确变更；若安装包超出上游体积限制，如实报告大小，不宣称符合该门槛。

## 验证与交付

- 为影响运行的版本分支、文件读取和回调生命周期补充有针对性的测试，执行现有单元测试、release lint 和 release 构建。
- 核查 APK 的实际最低 SDK、签名和大小。优先在 API 23 与现代 Android 测试环境中验证启动、应用发现和导航；缺失的测试环境在结果中明确标注。
- 交付可审阅的源码改动、补丁、APK 和简短使用说明。未测试的系统版本不声称已验证。
- 在 H2 安装实测前单独说明测试步骤；先作为普通应用验证，不接管开机或主页键，不停用原桌面。真实遥控器按键如需人工验证，再请求用户协助。
- 未经后续指令不推送、合并或发布 GitHub 变更。

## 验收标准

Android 6 的 APK 可正常安装并启动；应用列表、遥控器方向键、应用启动和设置入口可用；日期/主题与网络状态不因缺失 API 崩溃。现代 Android 保留现有行为。H2 是否能成为默认桌面属于固件策略，独立于应用兼容性验收。
